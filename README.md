# Supervised-Contrastive-Temporal-Smoothness

离散 token 序列 检索阶段要从后缀 
𝑛
n-gram 构造哈希索引，默认输入是离散的词 ID，通过 canonicalization 归一化后再进行多头哈希。

局部模式的静态存储 Engram 假设文本中存在大量“局部、静态、模板化”的模式可以直接查表而不必每次重新计算，这些模式可以用固定向量表示，并通过与动态隐藏状态的门控调节贡献。

您提到的信道处理中，数据张量形状是[B,slot,beam,re]，例如 34 个时隙、32 个波束、每束 96 维复数特征。这与 NLP 的离散序列有几处根本差异：

数据是连续的复/实值矩阵，而非离散 token。Engram 的哈希检索依赖于把 token ID 映射到素数大小的 embedding 表。在信道处理场景中若要使用类似结构，需要首先将连续信道特征进行量化、离散化或编码，才能作为哈希输入；否则无法直接用整数索引查表。

局部模式的含义不同。文本中的 n-gram 是自然的局部依赖；而无线信道的相关性跨越时间槽、频域子载波或天线束方向，并不一定适合用固定长度的“后缀 n-gram”描述。因此，如何定义“静态模式库”以及选择合适的哈希窗口是开放问题。

形状和维度匹配。Engram 在语言模型中通常插入到 transformer 的浅层，其输出形状与隐藏状态相同；针对形如 [B,34,32,96] 的张量，可以把 slot 作为“序列长度”，把 beam 和 re 维度通过 hyper‑connection 或分组方式对齐，但这需要重新设计检索和卷积模块以支持二维甚至三维局部模式。

综上，Engram 的核心思想——将静态局部模式和动态全局推理解耦——对信道处理具有启发意义，但并不能直接复用现有实现。若要应用于无线通信，需要：

自定义离散化/编码：例如把某些频域或空间域特征量化成离散码字，再用多头哈希检索固定模式；或者采用局部敏感哈希（LSH）等适用于连续向量的哈希方案。

重新定义局部窗口：根据信道的时间‑频率‑空间相关性确定适当的局部感受野，用二维或三维卷积代替论文中的一维卷积。

调整门控和融合：门控权值的计算可继续使用当前状态与静态记忆的相似度，但需要确定信道特征的归一化方式和投影维度。
